    Agent loop, not a graph
    Upstream is a fixed safety pipeline, so it uses an explicit LangGraph graph. Highbury's questions need different tools in a different order each time, so the model drives a LangChain agent loop. Guardrails live in middleware instead of graph edges.
    
      
    Postgres, read-only
    The agent connects as analyst_ro: SELECT only, statement timeout, row cap. sqlglot also rejects anything that isn't a single SELECT before it reaches the database. Two independent locks.
    
      
    Numbers are checked
    The answer is structured: every claim carries its value and the tool call it came from. The verifier compares each value with the recorded tool output before anything is shown.
    
      
    Charts are data
    The model never draws. It asks build_chart for a validated spec, and the frontend renders it with D3. The LLM decides what to show, the UI owns how it looks.
    
      
    Model is config
    init_chat_model makes the model a setting, so the eval suite can run the same 50 questions on several models and pick by accuracy, cost, and latency.
